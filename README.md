# TRIK Mind

[![CI](https://github.com/trikset/trik-mind/actions/workflows/python-app.yml/badge.svg)](https://github.com/trikset/trik-mind/actions/workflows/python-app.yml)
![Python](https://img.shields.io/badge/python-3.12-blue)

Сервер для выполнения инференса ML-моделей (ONNX / TFLite) на ПК и отправки результатов
на робота TRIK или в TRIK Studio по TCP.

## Установка

1. Скачайте архив для вашей платформы с последней версией сервера
   [здесь](https://github.com/trikset/trik-mind/releases/latest).
1. Распакуйте архив.
1. Отредактируйте `settings.ini` (см. ниже).

## Релизы

Релизы помечаются тегами вида `vYY.MM.DD` (например, `v26.08.03`). К каждому
релизу прикреплён один архив для каждой платформы — внутри лежит исполняемый
файл и `settings.ini`. Релиз сначала создаётся как черновик, а публикуется
после проверки сопровождающим.

Имена файлов содержат версию релиза, например
`TRIKMind-v26.08.03-Windows.zip`,
`TRIKMind-v26.08.03-Linux.tar.gz` или
`TRIKMind-v26.08.03-macOS.tar.gz`. Windows использует `.zip`,
Linux и macOS — `.tar.gz`. Внутри каждого архива лежит исполняемый файл с
версией в имени (`TRIKMind-v26.08.03.exe` для Windows,
`TRIKMind-v26.08.03.bin` для Linux/macOS).

## Системные требования

Документированный базовый уровень совместимости с ОС (продуктовое решение,
см. `MEMORY.md`). Изменение базового уровня — это изменение продукта: оно
требует обновления этого раздела и проверки сборок.

| ОС | Архитектура | Минимальная версия |
|---|---|---|
| Linux | x86_64 | glibc ≥ 2.28 (Ubuntu 20.04+, Debian 11+, RHEL 8+, Fedora 31+) |
| macOS | arm64 (Apple Silicon) | macOS 14 (Sonoma) |
| Windows | x86_64 | Windows 10 22H2+ |

Практическое следствие: Intel-версия macOS не поддерживается — для обеих
ML-библиотек (onnxruntime, LiteRT) больше не существует пакетов под x86_64;
минимальную версию macOS 14 диктует пакет onnxruntime.

## Настройка (`settings.ini`)

| Параметр | Описание |
|---|---|
| `SERVER_IP` | IP робота или студии. Для студии обычно `127.0.0.1` |
| `MY_HULL_NUMBER` | Борт-номер этого сервера. Выберите незанятый. |
| `SERVER_PORT` | Порт TCP-сервера на роботе/студии. Обычно `8889` |
| `MODEL_PATH` | Путь к папке с моделью. Оставьте пустым, если папка рядом с .exe |
| `VIEW_THRESHOLD` | Порог показа (0..1): ниже — метка не отображается в дашборде. Рекомендация: 0.4 |
| `SEND_THRESHOLD` | Порог отправки (0..1): ниже — роботу идёт `-1`. Рекомендация: 0.6 |
| `PHOTO_URL` | URL snapshot беспроводной камеры (например, `http://192.168.1.100:8080/?action=snapshot`). Оставьте пустым для других режимов |
| `GET_IMAGES_FROM_ROBOT` | `True` — получать кадр с камеры робота. `PHOTO_URL` должно быть пустым |
| `CAMERA_NUMBER` | Номер веб-камеры ПК (0, 1, 2…). Используется только если `PHOTO_URL` пуст и `GET_IMAGES_FROM_ROBOT=False` |
| `USERNAME` / `PASSWORD` | Аутентификация для `PHOTO_URL` (если требуется) |
| `OUTPUT_MODE` | Режим вывода: `user` (цветной, в stderr) или `stdout` (табуляция, в stdout). Раздел `[UI]` |
| `COLOR_ENABLED` | Цветной вывод: `true` / `false`. Только в режиме `user`. Раздел `[UI]` |

*Светлая тема (выше) — без ANSI-цветов, для терминалов без поддержки цвета.
Тёмная тема (ниже) — с ANSI-цветами: буквы меток на цветных подложках.*

Демонстрацию можно запустить вживую (без камеры и робота):
`uv run python TRIKMind.py --demo`. Скорость конвейера задаётся
`--fps N` — детекция происходит раз в 5 кадров, то есть N/5 раз в секунду
(по умолчанию 16 ≈ 3.2 детекции/с).

```
╭─Current──fruit_classifier.onnx│USB@640x480│W79>79+UTF8+VT1+COL1──────╮  ← модель, источник, диагностика
│ ★ Peach  83.7%                                          fps:32  #12  Δ 0.4s │  ← метка + уверенность + метрики
│  Apple(77%)  Banana(6%)                                     │  ← кандидаты ≥ VIEW_THRESHOLD
├─ History ──────────────────────────────────────────────────────────────┤
│Bar                                             %    # Label      Evt    │
│AAAAPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPP   55%   12  Peach,Apple   →↑│  ← буквы = возможные метки, A=Apple, P=Peach
│AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA   94%   11  Apple        ↑│  ← ↑ = отправлено роботу
│PPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPP   54%   10  Peach,Banana   ×│  ← × = показано, но НЕ отправлено
│PPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPP   53%    9  Peach,Banana   ×│
│░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░    ---  ---  ---          │  ← заполнители/ниже VIEW_THRESHOLD
├─ Stats ────────────────────────────────────────────────────────────────┤
│ Apple 12  Banana 10  Peach 8                                          │  ← все метки со счётчиками (алфавитно)
╰────────────────────────────────────────────────────────────────────────╯
```

### Элементы панели

| Элемент | Что показывает | Цвета и символы |
|---------|---------------|-----------------|
| **Заголовок Current** | Модель, источник видео, диагностика (ширина/кодировка/цвет) | Всегда виден, на одной строке с рамкой |
| **Строка метки** | Текущий распознанный объект, уверенность в %, FPS, номер детекции, время с последней смены метки (Δ) | ★ при свежей метке (\< 1 с); зелёный ≥80%, жёлтый ≥50%, красный \<50% |
| **Кандидаты** | Остальные возможные метки с уверенностью ≥ `VIEW_THRESHOLD` (текущая не повторяется) | 1‑я зелёная, 2‑я синяя, 3‑я пурпурная, остальные серые |
| **История** | Последние N детекций (заполняет оставшееся место терминала) | Бар = буквы меток (первая буква, уникальная) на цветной подложке: победитель — цвет уверенности (зел/жёлт/красн), 2‑я синяя, 3‑я пурпурная, остальные серые (░). Длина сегмента = доля метки в сумме уверенностей, бар всегда полный. `↑` = отправлено, `×` = показано-не-отправлено, `→` = смена метки |
| **Статистика** | Все метки со счётчиками, алфавитно, многострочно | Только текст, без полос |

Строки с `---` заполняют пустое место, чтобы статистика всегда была внизу;
`░` также показывает детекции, где ни одна метка не достигла
`VIEW_THRESHOLD` (виден только `%` победителя).

### Пороги (VIEW_THRESHOLD / SEND_THRESHOLD)

| Порог | Что делает | Рекомендация |
|-------|-----------|--------------|
| `VIEW_THRESHOLD` | Метки с уверенностью ниже порога **не показываются** (ни в истории, ни в кандидатах, только статистика). Детекция ниже порога показывается как `---` | 0.4 |
| `SEND_THRESHOLD` | Метка **отправляется роботу** только если её уверенность ≥ порога. Иначе роботу идёт `-1` (ничего не распознано) | 0.6 |

Метка, у которой уверенность между `VIEW_THRESHOLD` и `SEND_THRESHOLD`,
видна на панели (с меткой `×`), но роботу не отправляется — панель честно
показывает то, что модель «видела», а робот действует только на надёжные
детекции. Если ни одна метка не превысила `SEND_THRESHOLD`, робот получает
`-1` ровно столько же раз, сколько панель показывает `×`.

### Режимы

- **Нормальный** — модель уверена: одна метка с высоким процентом, остальные
  значительно ниже. Бар почти весь одного цвета.
- **Почти совпадение** — две метки оба выше `VIEW_THRESHOLD` и близки по
  уверенности (например, Apple 85% / Peach 78%): бар разделён на два почти
  равных сегмента с разными буквами — видно, что модель путает похожие классы.
- **Низкая уверенность** — все метки ниже `VIEW_THRESHOLD`: бар `░`, метка `---`.
- **Ошибка** — камера не дала кадра. Метка заменяется на `---`, роботу идёт `-1`.

### Бейдж соединения

Жёлтый текст на строке метки появляется при вызове `set_status("reconnecting")`:

```
│ ★ Banana  connecting  fps:27  #42  Δ 0.3s                           │
```

В режиме `stdout` (`-o stdout`) выводятся табулированные строки для передачи
в другие программы (grep, awk, логирование).

Лог-файл по умолчанию — `trik_mind.log` рядом с программой. Путь можно
изменить через `--log-file`.

## Подготовка модели

В папку модели положите `model.onnx` или `model.tflite` (или любой другой `.tflite`/`.onnx` файл).

Labels загружаются в следующем приоритете:

1. **`labels.txt`** — одна строка на класс. **Приоритет выше, чем signature.json**
1. **`signature.json` → `classes.Label`** — если `labels.txt` нет

### labels.txt (рекомендуется)

```
кошка
собака
птица
```

### `signature.json` (если нужно явное имя файла или нет labels.txt)

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `classes.Label` | да (если нет labels.txt) | Список имён классов |
| `filename` | нет | Имя файла модели (если в папке несколько) |

```json
{
    "classes": {"Label": ["кошка", "собака"]},
    "filename": "model.onnx"
}
```

**Microsoft Lobe (легаси)** — полный `signature.json` тоже работает, читается только `classes.Label` и `filename`.

## Использование

### С беспроводной камерой

```
PHOTO_URL=http://192.168.1.100:8080/?action=snapshot
GET_IMAGES_FROM_ROBOT=False
```

### С камерой TRIK

```
PHOTO_URL=
GET_IMAGES_FROM_ROBOT=True
```

Включите камеру на роботе перед запуском.

### С камерой ПК

```
PHOTO_URL=
GET_IMAGES_FROM_ROBOT=False
CAMERA_NUMBER=0
```

## Чтение данных в TRIK

Запустите скрипт на TRIK с помощью TRIK Studio:

```python
def main():
    while True:
        predict = mailbox.receive(True)
        print(predict)
        script.wait(1000)
```

## Параметры командной строки

| Параметр | Описание |
|---|---|
| `-o, --output-mode <user|stdout>` | Режим вывода. `user` — цветной вывод в stderr (по умолчанию). `stdout` — табулированный вывод для pipe |
| `--no-color` | Отключить ANSI-цвета (только в режиме `user`) |
| `-v, --verbose` | Подробный вывод в stdout-режиме. Можно указать дважды: `-v -v` |
| `--log-file PATH` | Путь к лог-файлу (по умолчанию `trik_mind.log`) |
| `--demo` | Демонстрационная приборная панель с фейковыми предсказаниями — без камеры и робота |
| `--fps N` | Частота кадров конвейера в режиме `--demo`; детекция раз в 5 кадров (N/5 в сек., по умолчанию 16) |
| `--version` | Показать версию программы и выйти |

## Поддерживаемые модели

Сервер работает с любой моделью классификации изображений:

- **ONNX** (`*.onnx`) — прямой запуск через onnxruntime.
- **TFLite** (`*.tflite`) — прямой запуск через ai_edge_litert (LiteRT).

Формат авто-определяется по расширению файла. Labels — из `labels.txt` или `signature.json` → `classes.Label` (приоритет у `labels.txt`).
